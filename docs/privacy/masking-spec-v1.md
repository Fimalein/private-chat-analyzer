# LLM向けトーク履歴マスキング仕様 v1（提案・未リリース）

**Status:** Design draft, 2026-10-25. Related: [#49](https://github.com/Fimalein/private-chat-analyzer/issues/49), [#46](https://github.com/Fimalein/private-chat-analyzer/issues/46), [Draft PR #47](https://github.com/Fimalein/private-chat-analyzer/pull/47), [脅威モデル](llm-provider-disclosure-threat-model.md)。

> 目的は、利用者が選んだLLMに**必要な会話を意図的に渡す**前に、第三者の識別子・秘密情報の提供を抑えること。公開データセット並みの不可逆匿名化を要求しない。マスキングは漏洩リスクを下げるが、絶対的な安全性・非特定性や提供先による即時削除は保証しない。

## 0. 境界と非目標

1. LINE / Meta / Telegramの元ファイルと source→replacement の対応表は**端末内**で処理する。ChatGPT・GitHub・解析サービス・CIへ自動送信しない。
2. 明示承認後のファイルをLLMサービスへ手動提供する場合、そのサービスは本文を読むことができる。暗号化通信・ChatGPTの学習オプトアウトと、提供先が**一切保持しないこと**は同義ではない。
3. 当面はテキストメッセージのみを保証対象とする。添付画像・音声・動画・OCR・埋め込みリンク先コンテンツ、アプリやブラウザ拡張が独自に送信する内容を「検査済み」と表示しない。未対応の外部データは出力対象から除外する。
4. 機微な会話には本人以外の情報が含まれる。相手の同意・第三者への影響や分析目的も確認事項であり、ユーザー本人の承認だけで第三者の全ての権利や期待が解決するわけではない。
5. 実際のチャット、識別子の対応表、スクリーンショット、実際のログは**公開リポジトリのコード・Issue・PR・CIへ掲載禁止**。検証は完全に合成したフィクスチャのみ。

## 1. 情報分類と基本動作

| 区分 | 具体例 | v1の原則 | 利用者による「そのまま送信」の解除 |
|---|---|---|---|
| **S0 秘密情報** | パスワード、APIキー、OAuth/Bearer token、セッションCookie、秘密鍵、認証付き共有URL、ワンタイムコード | **ハードブロック**。元テキストで候補を検出し、対象部分を削除／置換してから再検査する。秘密文字列をUI以外のログ・エラー・解析Indexへ出さない | **不可**。検出漏れはあり得るため最終目視確認も必須 |
| **P1 直接識別子** | 氏名・愛称・ユーザーID、メール、電話、住所、所属と個人の一意な組み合わせ、学籍・社員・口座番号 | **既定で仮名化または伏字**。検出漏れと誤検出をレビューで提示し、必要性のある非秘密情報のみ意図的に残せる設計 | **条件付き**。何が残るか・誰に届くかを表示し明示レビュー |
| **P2 準識別子・機微文脈** | 学校・勤務先・地域、正確な日付、希少な出来事、病歴・家族・恋愛関係、複数メッセージの組み合わせ | **意味を保持して注意喚起**。学校A、会社Bなどの置換と日付粗化を提案。珍しい出来事を全消去することは必須としない | **可**。目的に必要な文脈かを人間が判断 |
| **U 分析に必要な情報** | 発話順序、話者区別、言語、感情表現、返答間隔、会話の流れ | なるべく保持。出力の内容が実データからどのように変換されたか明示 | 対象外 |

**S0を見つけた場合**は、その部分を除去して再スキャンするまで出力を停止する。「危険を承知したのでそのまま残す」ボタンは作らない。パターン未検出の秘密情報も存在し得るため、検出器の通過は安全性の証明ではない。

**P1とP2**は同一の機械的基準で禁止しない。解析目的に必要な文脈と第三者のプライバシーとのトレードオフを表示する。追加の「extra-strict」モードは[#46](https://github.com/Fimalein/private-chat-analyzer/issues/46)で別途維持する。

## 2. 処理パイプライン（順序の固定）

```text
Local input (原本不変 / outside GitHub)
  -> Scope selection (期間/メッセージ範囲/話題、ユーザーが選ぶ)
  -> Normalize view for detection (Unicode, full/half width, CRLF, encodings)
  -> S0 secret/credential scan against ORIGINAL selected data
  -> P1 structured PII & selected local alias rules
  -> P2 proper nouns / contextual clues as candidate suggestions
  -> Human review: omit, mask, pseudonymize, or explicitly keep non-S0 facts
  -> Apply deterministic mappings and edits (local-only)
  -> Serialize the ACTUAL outgoing set: .txt / .jsonl / analysis_index.json / instructions
  -> Rescan ALL artifacts (literal + JSON/JSONL-decoded + relevant encoded variants)
  -> Freeze preview + intended receiver + data handling notice
  -> Human approval bound to exact files, scope, recipient and settings
  -> User-initiated local download or native share (NO automatic LLM API request)
```

規則:
- 各フィールドを個別に検査（本文、話者名、ID、ファイル名、Index、指示文、日時・元ソース情報）。「本文だけ安全」は不十分。
- UTF-8、全角/半角、NFKC、不可視文字、URLエンコード、HTMLエンティティ、JSON escape、Base64等を検査用に正規化。**原文は検査のために破壊しない**。過剰な正規化による誤検出・文字位置ずれもテストする。
- 検出対象が部分的に重なるときはS0を最優先。候補が曖昧な場合は勝手に安全扱いせず、理由・発生箇所を示す。
- 置換は**元の文字列に対して一度だけ適用**（置換後の語を再び置換しない）。長い別名を先に処理し、同じ人物の複数呼称は同じ安定した仮名へ集約。人ごとに通し番号を決めても、実名と仮名の対応表は出力しない。
- 固有名詞の自動認識（日本語NER）は**候補生成**であり単独の「安全ゲート」ではない。固有名詞を網羅的に検出できるという表示は禁止。
- エラーはカテゴリや件数のみを記録。失敗した原文、候補、送信先URLパラメータをコンソール・テレメトリ・CIログに記録しない。

## 3. 使いやすさと同意UI

- **共有モード:** (A) ローカル解析のみ、(B) レビュー済みLLM共有（標準）、(C) 追加の厳格なマスキング（任意）。
- **対象選択:** メッセージ範囲と期間を主軸にし、後からキーワード周辺・話題単位も追加する。「直近5件」などは安全寄りの初期値であって唯一の選択肢にはしない。長文の関係分析には広い範囲を選択できるようにする。
- **候補レビュー:** S0は解除不可。P1は既定でマスク、見逃し疑いは目視。P2は「地域A」「大学B」等の置換・省略・保持を選べる。正規表現ヒットを実際の個人情報と断定しない。
- **出力プレビュー:** 最終的に送る**すべてのファイルの全文**を表示。過去のマスキング決定だけでなくシリアライズ後もチェックする。
- **提供先確認:** ChatGPT通常 / Temporary / その他。学習利用・保存・サードパーティツールの注意、公式ルールへのリンクと確認日を表示。ChatGPTアカウント設定をアプリが確認したという主張は禁止。提出後の保存は受信側の方針に依存する。
- **承認の失効:** 元会話/対象範囲/置換表/検出・マスク規則/ファイル本文/提供先/日付モードが変われば承認を破棄。共有直前に同じ出力を再計算・照合し、差分があればブロック。
- **誤操作防止:** プレビューだけで自動アップロード・自動共有しない。通常のダウンロードとネイティブ共有の区別を明記し、OSの共有先を勝手に選ばない。

## 4. v1安全性・品質検査（実際のチャットは使用禁止）

### 合成サンプル必須カテゴリ

| ID | 合成テストの例 | 期待結果 |
|---|---|---|
| S0-01 | 架空のBearer / JWT / GitHub token形式・パスワード・鍵ヘッダー・cookie | 原文の秘密候補を検出して除去前にブロック。マスク後は全4ファイルを再検査 |
| S0-02 | URLクエリ・URL fragment・JSON / multiline文字列・エンコードされた認証情報 | 直接検査に加え、デコードされた残存値を出力後検査（未対応はブロック／明示） |
| P1-01 | 架空の日本語名と愛称、同人物の表記揺れ、話者IDと本文の再登場 | 同一人物は一貫した仮名、ソース値や対応表は4ファイルに含めない |
| P1-02 | 架空のメール（example.test）、+81表記、ハイフン/空白違いの電話・住所断片 | 対応する検出候補が出る。原型・正規化・誤検出の両方を検証 |
| P2-01 | 架空の学校・地域・希少な学会・個人の時系列 | 自動削除せずレビュー候補として扱い、必要な会話順序は保存 |
| F-01 | 本文だけ安全で JSONL / Index / 指示文 / ファイル名に元値が混入 | 出力直前の横断検査でブロック |
| F-02 | 長い発話、CRLF、改行、絵文字、結合文字、全半角、HTML/URL/JSON escape | マスク範囲がずれない。未対応の形式・巨大サイズは安全側で失敗 |
| UI-01 | 承認前ダウンロード、承認後の編集、送信先変更、複数ウィンドウ操作 | 明示承認までは不可、いずれの変更でも承認が失効 |
| NET-01 | Chromium上の合成LINEインポート→レビュー→プレビュー→共有前 | 意図しない外部HTTP/WebSocket通信0、合成canary送信0 |
| NET-02 | Android相当の操作・外部フォント/ワーカー/端末拡張・キャッシュ | 別途実機・ネットワーク調査。Chromium合格のみで完了にしない |

テスト用の疑似認証情報は**実在・有効な鍵を使用しない**。テストが失敗しても、出力するのはケースID・件数・理由コードのみ。合成文字列自体をネットワークへ送らない。

### リリース判定

1. 既知の合成S0秘密文字列が、**4ファイルすべてで0件残存**。既知の合成元識別子・対応表も出力に0件残存。誤検出で不必要に内容を失っていないか個別に評価する。
2. 検出器の **entity-level recall / precision、未検出の種類、false positive** を分離して報告（日本語名、住所、S0、符号化ケース別）。未使用の固定holdoutを評価し、調整に使ったケースを独立評価と偽らない。未検出率が十分に小さいとの根拠がない限り「自動的に安全」表示禁止。
3. プレビュー対象と最終出力のバイト一致、編集・相手変更による承認失効をテスト。標準とextra-strictの差を明示し混同しない。
4. **合成データを用いたブラウザネットワーク検査**が0件の意図しない外部通信を示す。Android/実機等の未検証条件は明示して出荷判断する。
5. 利用者の明示的なダウンロード・共有以外でプロバイダーへ転送しない。サービス側の保持・学習・削除はアプリから強制できないため、説明文が最新か確認する。
6. 残ったブロッカーはIssue化し、保留中に「安全に送れる」などの絶対的な保証を表示しない。

## 5. 実装との差分（2026-10-25 時点でコードを確認）

| 既存機能 | 観測した状態 | v1で追加すること |
|---|---|---|
| `src/lib/privacy/structured-pii.ts` | メール/電話/URL/IPv4/郵便番号/長い数字/一部credentialを検出。7分類、high/medium | S0とP1を明確に分離。Cookie、PEM/private-key、認証付きURLなどの多様な形式、非典型なUnicode・折返し検出を拡充し、誤検出も検証 |
| `src/lib/privacy/entity-map.ts` | 完全一致の置換、長い文字列優先、一段階置換。複数の呼び名は`familyId`で管理可能 | 氏名/愛称候補をローカルレビューで統合。表記揺れ・境界・重なりの誤置換テスト |
| `src/lib/export/strict-chatgpt-share.ts` | 少量メッセージを選び、4出力の検査・再照合。高/中の構造化個人情報を厳格に遮断 | 追加の厳格モードとして残し、LLM標準共有に「完全な匿名化」を強制しない |
| `src/components/ChatGptExportLauncher.tsx` | 受信先選択・保持条件の説明・同意ゲートを追加。標準経路は事前に最終4ファイルを個別レビューさせてはいない | v1標準モードでもプレビュー全文・再照合・S0ハードブロック・範囲選択を導入。現在の標準経路を安全認証済みと扱わない |
| `scripts/audit-browser-network.cjs` | 合成LINE履歴→仮名化→strict preview→標準送信先確認で0件の外部通信を確認 | キャンセル・別入力・モバイル・ネットワーク境界の負のテスト、適用範囲を文書化 |
| `PR #45` NER研究 | 実験段階。日本語名・住所で既知の未検出がある | 候補提示に限定。独立ホールドアウトによる根拠なしに必須・安全判定へ昇格させない |

## 6. 実装の順序（PRは小分け）

1. **P0: S0認証情報の分類・原文検出・強制ブロックを整備**し、合成fixtureと各4出力のテスト追加。
2. **P0: 標準LLM共有にも出力全文プレビュー + チェック前送信禁止**を追加。承認にscope/mapping/recipient/file hashを結びつける。
3. **P1: P1候補の連続性ある仮名化**（名前/愛称/学校/住所/組織のローカル確認UIと偽陽性対応）。
4. **P1: 広い期間・話題ごとの選択機能**と目的ベースの最小化。
5. **P1: 独立合成holdout評価・Android端末監査**、可能ならプライバシー強化されたローカル推論で固有名詞候補を補助。

この仕様は議論・実装の基準であり、**記載された機能がすべて実装・検証済みという意味ではない**。
